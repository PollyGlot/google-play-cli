gplay 2.0.0 gives every concept one flag name and one verb, and makes the JSON
error envelope name what failed on any kind of resource, not only packages.

The old names are **removed, not aliased**
([ADR-0048](https://github.com/PollyGlot/google-play-cli/blob/main/docs/adr/0048-v2-release-train.md)).
A 1.x spelling fails before any API call, with exit `2` and
`"code": "USAGE_ERROR"` naming the unknown flag or command, so a stale CI
script stops on its first run instead of doing something else.

This page lists every change between `1.6.1` and `2.0.0`. The releases in
between (`1.6.2`, `1.7.0`) removed nothing from the Public contract; their
fixes are in the
[changelog](https://github.com/PollyGlot/google-play-cli/blob/main/CHANGELOG.md).

## Checklist

1. Rename the flags and commands your scripts call: [tables](#renamed-flags-and-commands),
   or the [`sed` recipe](#update-a-ci-script-with-sed).
2. If you parse `error.package` from the JSON error envelope, read
   [`error.resource`](#the-error-envelope-gains-resource) instead.
3. On Homebrew, [switch from the formula to the cask](#homebrew-from-formula-to-cask) once.
4. If an agent drives gplay, run `gplay install-skills` again after upgrading
   ([Agent skills](#agent-skills)).

:::tip[What does not change]
- **Exit codes.** The same 13 codes, with the same meanings and retry
  semantics as in 1.6.1 (only the wording of `2` and `4` in
  `gplay exit-codes` was clarified). See [Exit codes](/docs/concepts/exit-codes/).
- **API pass-through JSON.** `--output json` still mirrors the Google Play API
  response verbatim, and success output is untouched.
- **stderr.** The human error line still reads `<operation> on <id>: ...`.
- **Every flag and command not listed below**, including
  `releases promote --from/--to <track>`.
- **What is on disk.** Stored Accounts, credentials and the `.gplay/` files
  carry over as they are.
:::

## Renamed flags and commands

Old name on the left, its replacement on the right. Values keep their format
unless a note says otherwise.

### Public contract (frozen)

| 1.x | 2.0.0 |
| --- | --- |
| `gplay releases rollout --to <fraction>` | `gplay releases rollout --staged <fraction>` |
| `gplay vitals anr --version <versionCode>` | `gplay vitals anr --version-code <versionCode>` |
| `gplay vitals crashes --version <versionCode>` | `gplay vitals crashes --version-code <versionCode>` |
| `gplay vitals errors counts --version <versionCode>` | `gplay vitals errors counts --version-code <versionCode>` |
| `gplay vitals excessivewakeup --version <versionCode>` | `gplay vitals excessivewakeup --version-code <versionCode>` |
| `gplay vitals lmk --version <versionCode>` | `gplay vitals lmk --version-code <versionCode>` |
| `gplay vitals slowrendering --version <versionCode>` | `gplay vitals slowrendering --version-code <versionCode>` |
| `gplay vitals slowstart --version <versionCode>` | `gplay vitals slowstart --version-code <versionCode>` |
| `gplay vitals stuckbgwakelock --version <versionCode>` | `gplay vitals stuckbgwakelock --version-code <versionCode>` |
| `gplay metadata images apply --no-validate` | `gplay metadata images apply --skip-preflight` |

- `releases rollout --staged` takes the same fraction `--to` took
  (`0 < f ≤ 1.0`, e.g. `0.05`), now parsed as a number, like `--staged` on
  `releases upload` and `releases promote`. `releases promote --to <track>` is
  a different flag and keeps its name.

### Experimental

[Experimental](/docs/concepts/stability/) commands may change in any release;
2.0.0 aligns them with the same vocabulary.

| 1.x | 2.0.0 |
| --- | --- |
| `gplay games achievements list --max-results <n>` | `gplay games achievements list --page-size <n>` |
| `gplay games leaderboards list --max-results <n>` | `gplay games leaderboards list --page-size <n>` |
| `gplay games achievements create --from-json <file>` | `gplay games achievements create --file <file>` |
| `gplay games leaderboards create --from-json <file>` | `gplay games leaderboards create --file <file>` |
| `gplay games achievements update <id> [--from-json <file>]` | `gplay games achievements set <id> [--file <file>]` |
| `gplay games leaderboards update <id> [--from-json <file>]` | `gplay games leaderboards set <id> [--file <file>]` |
| `gplay games achievements delete <id>` | `gplay games achievements remove <id>` |
| `gplay games leaderboards delete <id>` | `gplay games leaderboards remove <id>` |
| `gplay subscriptions prices migrate --region US --region CA` | `gplay subscriptions prices migrate --regions US,CA` |
| `gplay releases artifacts list --kind apk\|bundle` | `gplay releases artifacts list --format apk\|bundle` |
| `gplay appstore update --file <json>` | `gplay appstore submit --file <json>` |
| `gplay appstore publish-status <published\|unpublished>` | `gplay appstore publish-status set <published\|unpublished>` |
| `gplay appstore upload apk <file.apk>` | `gplay appstore apk upload <file.apk>` |
| `gplay appstore upload image <file>` | `gplay appstore image upload <file>` |
| `gplay appstore upload policy <file>` | `gplay appstore policy upload <file>` |
| `gplay appstore catalog events list --start-time <t> --end-time <t>` | `gplay appstore catalog events list --since <t> --until <t>` |
| `gplay reviews history --from YYYY-MM --to YYYY-MM` | `gplay reviews history --since YYYY-MM --until YYYY-MM` |

- `--regions` takes a comma-separated list or a repeated flag:
  `--regions US,CA` and `--regions US --regions CA` are the same.
- `appstore catalog events list --since/--until` take the same RFC 3339
  times, over the same `[since, until)` range.
- `reviews history --since/--until` take the same `YYYY-MM` months, both
  included. `--month` is unchanged.

### gplay-authored output that follows the renames

Only text gplay writes itself changes; API pass-through JSON does not.

- The `verb` field of the `games achievements set --dry-run` and
  `games leaderboards set --dry-run` JSON reads `set achievement` /
  `set leaderboard` (was `update achievement` / `update leaderboard`).
- The markdown headings of the appstore commands name the new paths
  (`## appstore submit`, `## appstore apk upload`, ...).

### Update a CI script with sed

This rewrites every 1.x spelling above in place and keeps a `.bak` copy of each
file. It runs on both GNU and BSD (macOS) `sed`:

```bash
sed -E -i.bak \
  -e '/gplay[[:space:]].*vitals[[:space:]]/s/--version([[:space:]=])/--version-code\1/g' \
  -e '/gplay[[:space:]].*releases[[:space:]]+rollout/s/--to([[:space:]=])/--staged\1/g' \
  -e '/gplay[[:space:]].*metadata[[:space:]]+images[[:space:]]+apply/s/--no-validate/--skip-preflight/g' \
  -e '/gplay[[:space:]].*games[[:space:]]/s/--max-results/--page-size/g' \
  -e '/gplay[[:space:]].*games[[:space:]]/s/--from-json/--file/g' \
  -e 's/(games[[:space:]]+(achievements|leaderboards)[[:space:]]+)update([[:space:]]|$)/\1set\3/g' \
  -e 's/(games[[:space:]]+(achievements|leaderboards)[[:space:]]+)delete([[:space:]]|$)/\1remove\3/g' \
  -e '/gplay[[:space:]].*prices[[:space:]]+migrate/s/--region([[:space:]=])/--regions\1/g' \
  -e '/gplay[[:space:]].*artifacts[[:space:]]+list/s/--kind([[:space:]=])/--format\1/g' \
  -e 's/(appstore[[:space:]]+)update([[:space:]]|$)/\1submit\2/g' \
  -e 's/(appstore[[:space:]]+publish-status[[:space:]]+)(published|unpublished)/\1set \2/g' \
  -e 's/(appstore[[:space:]]+)upload([[:space:]]+)(apk|image|policy)([[:space:]]|$)/\1\3\2upload\4/g' \
  -e '/gplay[[:space:]].*catalog[[:space:]]+events/s/--start-time/--since/g' \
  -e '/gplay[[:space:]].*catalog[[:space:]]+events/s/--end-time/--until/g' \
  -e '/gplay[[:space:]].*reviews[[:space:]]+history/s/--from([[:space:]=])/--since\1/g' \
  -e '/gplay[[:space:]].*reviews[[:space:]]+history/s/--to([[:space:]=])/--until\1/g' \
  .github/workflows/*.yml scripts/*.sh
```

Point it at your own files. Each flag rule only fires on a line that also names
the command, so `node --version` or `releases promote --to production` are left
alone. The flip side: a flag on a `\` continuation line, or a command built from
a variable, is not rewritten. List what is left and fix it by hand:

```bash
grep -nE -- '--(version|no-validate|max-results|from-json|region|kind|start-time|end-time)([[:space:]=]|$)|(achievements|leaderboards)[[:space:]]+(update|delete)|appstore[[:space:]]+(update|upload|publish-status[[:space:]]+(un)?published)|(rollout|history).*--(to|from)([[:space:]=]|$)' \
  .github/workflows/*.yml scripts/*.sh
```

A hit on another tool (`node --version`) is fine; every other hit is a 1.x
name to rename.

## The error envelope gains `resource`

Under `--output json`, a failing command writes an error envelope to stdout
([Output formats](/docs/concepts/output-formats/#stdout-vs-stderr)). In 2.0.0:

- `resource: {kind, id}` names what the failed call addressed, on whichever
  axis the command uses. It is omitted when the failure has no target (a usage
  error, for instance).
- `package` only ever holds an Android package name. It is present exactly
  when `resource.kind` is `package`, with the same value.

In 1.x, `package` also carried other identifiers. Those now move to `resource`:

| Commands | 1.x `error.package` held | 2.0.0 `error.resource.kind` |
| --- | --- | --- |
| `team ...`, `customapps create` | the developer account ID | `developerAccount` |
| `games ...` | the games application, achievement or leaderboard ID | `gamesApplication`, `achievement`, `leaderboard` |
| `reviews history` | the Cloud Storage bucket | `bucket` |
| `signing enroll` / `rotate` with a numeric app ID | the app ID | `app` |
| every package-scoped command | the package name (unchanged) | `package` |

A refused `gplay team users list`, before:

```json
{"error":{"code":"PERMISSION_DENIED","exitCode":11,"retryable":false,"operation":"users.list","package":"1234567890123456789","message":"users.list on 1234567890123456789: The caller does not have permission (HTTP 403)"}}
```

and in 2.0.0:

```json
{"error":{"code":"PERMISSION_DENIED","exitCode":11,"retryable":false,"operation":"users.list","resource":{"kind":"developerAccount","id":"1234567890123456789"},"message":"users.list on 1234567890123456789: The caller does not have permission (HTTP 403)"}}
```

A package-scoped failure keeps `package` and adds
`"resource":{"kind":"package","id":"<package>"}`.

The rule for a consumer: read `error.resource.id` (and `error.resource.kind`)
for "what failed", and treat `error.package` as present only on the package
axis. A script that must run against 1.x and 2.0 alike can fall back:

```bash
jq -r '.error.resource.id // .error.package // empty'
```

`kind` is an open list: new kinds may be added, existing ones never change
meaning.

## Homebrew: from formula to cask

The tap now ships gplay as a **cask** (macOS and Linux) instead of a formula,
and `brew` does not move a formula install over by itself: `brew upgrade`
leaves you on the last 1.x formula. Switch once:

```bash
brew list --formula gplay        # prints the formula if you have it
brew uninstall --formula gplay
brew install --cask PollyGlot/tap/gplay
gplay version
```

Uninstall the formula first. Installed side by side, the cask skips linking
`gplay` and the old formula binary stays first on your `PATH`.

If `brew update` warns that it is "Not automatically installing
pollyglot/tap/gplay because the migration target is not trusted" and suggests
`brew trust`, run the commands above instead: following that suggestion alone
installs the cask but leaves the formula binary on your `PATH`.

The install script, `go install`, and the release archives are unaffected:
same binary, same name.

## Agent skills

`gplay install-skills` installs the skill pack pinned inside the binary, and
the 1.x pack still uses the 1.x names. After upgrading, run it again to replace
the pack with the one pinned by 2.0.0:

```bash
gplay install-skills
```

Skills or prompts you wrote yourself need the renames from the
[tables above](#renamed-flags-and-commands). See [Agent skills](/docs/agents/skills/).

## Downgrading

2.0.0 changes nothing on disk, so rolling back to 1.7.x is safe. Your scripts
then need the 1.x names again: restore the `.bak` copies the `sed` recipe left.
