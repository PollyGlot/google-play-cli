# Publish only the agent-discovery surfaces that map to something real

## Status

accepted

## Context

`gplay`'s positioning is "built for CI and AI agents," and the site already
ships an agent surface — `llms.txt`/`llms-full.txt` and an AI-crawler-friendly
`robots.txt` ([ADR-0025](./0025-website-served-from-install-worker.md)). A
Cloudflare "is it agent-ready" scorecard (isitagentready.com) graded `gplay.sh`
against a broader framework and flagged several missing signals across two
groups:

- **Discovery / content:** no `Link` response headers (RFC 8288), no Markdown
  content negotiation, no DNS-for-AI-Discovery records.
- **"API, Auth, MCP & Skill Discovery":** no RFC 9727 API catalog, no
  OAuth/OIDC discovery, no OAuth Protected Resource metadata, no `auth.md`
  agent-registration doc, no MCP Server Card, no Agent Skills Discovery index.

The scorecard is a generic checklist. Most of its "API/Auth/MCP" items describe
a product that exposes a **protected web API or an MCP server** — which `gplay`
is not. `gplay` is a single static binary that calls *Google's* API with the
operator's own service-account credentials, plus a set of companion agent skills
([ADR-0021], repo `PollyGlot/google-play-cli-skills`). Chasing the full
checklist would mean publishing metadata for infrastructure that does not exist.

## Decision

**Publish exactly the discovery surfaces that correspond to something `gplay`
actually has, and no more.** Three surfaces, all in the site/Worker:

1. **Markdown for Agents.** `website/src/pages/[...slug].md.ts` emits a Markdown
   twin of every docs page at `<page>.md`. The Worker negotiates on
   `Accept: text/markdown` (GET, when Markdown is ranked ≥ `text/html`), serving
   the page's `.md` — or `llms.txt` for the landing page, which has no Markdown
   source — with `Content-Type: text/markdown` and `Vary: Accept`.
2. **`Link` headers (RFC 8288)** on every HTML document, pointing at the docs
   (`service-doc`), `llms.txt` (`describedby`), and the skills index (an
   extension relation URI).
3. **Agent Skills Discovery index** at `/.well-known/agent-skills/index.json`
   (RFC v0.2.0). Generated by `website/scripts/gen-agent-skills.mjs` from a local
   clone of the skills repo: each entry's `url` points at the canonical
   `SKILL.md` on `main` and `digest` is its SHA-256, so the index advertises the
   skills without duplicating their content.

## Why this shape

1. **Honesty over score.** A higher grade earned by publishing a fake
   `openid-configuration` or an empty `api-catalog` misrepresents the product.
   The three surfaces above each describe a real artifact (docs Markdown, the
   site, the published skills); an agent that follows them gets something true.
2. **Reuses what exists.** Markdown twins fall out of the same content
   collection that builds the docs; the skills index points at the skills repo
   that already ships. No new runtime, no new service.
3. **No new trust boundary.** All three are static assets or pure-JS header
   logic in the existing Worker — the minimal `Workers Scripts:Edit` token and
   manual-DNS discipline from ADR-0009/0025 carry over unchanged.

## What we lose / accept

- **The scorecard's "API/Auth/MCP" category stays mostly red.** That is the
  correct signal for a CLI with no hosted API — we accept the lower number.
- **`Vary: Accept` on HTML documents** lowers edge-cache efficiency slightly.
  At this traffic it is negligible (the Worker already runs on every request,
  ADR-0025) and it is the correct header for content negotiation.
- **The skills index digests can drift** if the skills repo changes and the
  index is not regenerated. The v1 skill set is stable; `npm run gen:skills`
  re-syncs it, and the generator assumes a checkout in sync with the skills
  repo's `main`.

## Considered and rejected

- **RFC 9727 API catalog (`/.well-known/api-catalog`).** Advertises a web API.
  `gplay` has none — it is a client of Google's API, not a server. A catalog
  would point nowhere.
- **OAuth/OIDC discovery, OAuth Protected Resource, `auth.md`.** All describe an
  authorization server / protected resource. `gplay` authenticates to Google
  with the operator's own service account; there is no `gplay` auth server to
  discover.
- **MCP Server Card (`/.well-known/mcp/server-card.json`).** `gplay` ships a CLI
  and skills, not an MCP server. **Whether `gplay` should offer an MCP server is
  a genuine product question** — tracked in `docs/BACKLOG.md`, not pre-empted by
  publishing a card for a server that does not exist. If one ships, the card
  becomes legitimate then.
- **DNS for AI Discovery (DNS-AID).** An immature IETF draft requiring signed
  DNS records; conflicts with the manual, out-of-CI DNS discipline of ADR-0009.
  Deferred until the standard settles.
